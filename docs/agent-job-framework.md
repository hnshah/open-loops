# The agent-job framework

Open Loops is intentionally one job.

That narrowness makes it useful for thinking about what kinds of responsibilities agents may be able to own repeatedly.

A durable agent job appears to have seven properties.

## 1. Persistent state

There is something worth continuously understanding.

For Open Loops, that state is unresolved obligations and dependencies.

## 2. Repeated incoming evidence

New evidence arrives over time.

Messages, meetings, calendar changes, files, and project records can create or close loops.

## 3. Judgment

The system must decide what matters rather than simply mirror records.

Open Loops judges obligation strength, closure, ownership, importance, urgency, and uncertainty.

## 4. Bounded output

The useful result is legible.

Open Loops returns a small evidence-backed brief instead of an endless inferred queue.

## 5. Feedback

The user can correct the judgment cheaply.

Corrections such as “already done,” “this matters,” or “never treat casual coffee as a commitment” are more useful than long configuration screens.

## 6. Repetition

The job becomes more valuable when it can run again against new evidence.

Repetition should happen only after the single run is good enough.

## 7. Increasing trust

Autonomy can progress in stages.

```text
find
→ explain
→ prepare
→ queue
→ execute with approval
→ routine ownership
```

Open Loops v0.x intentionally concentrates on the first three stages.

## Why this matters

Many agent demos are one-shot transformations. A job with state, incoming evidence, judgment, bounded output, correction, repetition, and graduated autonomy has a better chance of becoming delegated responsibility.

The question behind Open Loops is therefore larger than “can an LLM extract tasks?”

It is:

> Can I give an agent responsibility for noticing unfinished work so I no longer have to?
