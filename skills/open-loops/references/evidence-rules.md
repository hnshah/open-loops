# Evidence rules

Every surfaced loop must answer one question.

**Why do you believe this is still unfinished?**

## Evidence packet

Preserve enough information to make the judgment inspectable.

Prefer

- source type
- timestamp
- person, thread, event, or document
- short relevant excerpt or faithful paraphrase
- source link or identifier when the runtime provides one
- later resolution evidence checked

Do not copy large private passages into the output. Use the minimum excerpt needed to support the judgment.

## Evidence strength

### High

Clear obligation plus a strong search for later closure.

### Medium

Likely obligation or likely open state, but one important element remains ambiguous.

Examples

- only one source could be checked
- ownership is implied rather than explicit
- the expected time is approximate

### Watching

The candidate may become open later but is not yet actionable.

Example

Someone promised a document tomorrow and today is still before the expected delivery time.

### Probably fine

A candidate was detected but intentionally suppressed because the evidence is too weak, the interaction naturally concluded, or later context probably resolved it.

## Contradictory evidence

When sources conflict

1. prefer later evidence over earlier evidence when it clearly updates state
2. prefer direct evidence of delivery or cancellation over an inference
3. state uncertainty if the conflict cannot be resolved
4. do not choose the interpretation that produces a more exciting loop

## Source scope

Do not write "I found no evidence anywhere" when only one source was checked.

Use bounded language such as

- "I found no later evidence in the checked email thread."
- "No closure was found across the authorized email and Slack sources."

Trust comes from saying what was actually checked.
